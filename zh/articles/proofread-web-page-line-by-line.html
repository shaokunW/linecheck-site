阅读场景

发布前再检查一遍，哪些文字是真的检查过了？

文章已经写完，预览也打开了。你准备发布前再检查一遍，却发现自己说不清：哪些段落刚刚认真看过，哪些只是眼熟。

因为内容是自己写的，你很清楚它“应该”表达什么。视线经过一句话时，脑中读出来的，有时更像预期的句子。中途再被消息打断，回来后，前后几段看上去都像已经检查过了。

这一次，可以给“已检查”和“还有疑问”两个不同的可见状态。判断仍然由你来做，标记负责留住判断的进度。

先打开读者最终会看到的页面

在 Chrome 中打开普通 HTML 文章预览，或者已经发布的网页正文。这里讨论的是检查渲染后的文字，不是在富文本编辑器、嵌入式文档或 PDF 阅读器里直接改稿。

先完整读一遍，确认标题和正文有没有对上，结尾是否回应了开头。然后再开始细查，并给这一轮选定一个重点：是检查名称和数字，还是检查措辞和标点？如果什么都想一次检查，绿色标记也会变得含糊。

让绿色代表一件明确的事

开启 LineCheck，读完当前行，并完成这一轮约定的检查后，按 Enter 标绿。准备好了再用方向键往下走。碰到拿不准的地方，用 F 标红，留待复查。

绿色可以表示“这一行的人名和数字已经核对”，不必表示“这一句绝对没有问题”。红色可以表示“日期要查来源”或“这句转折要连着上一段再读”。需要记录具体原因时，写在你自己的笔记里，不要指望颜色替你记住全部细节。

发布前，可以分开检查这几件事

  • 名称和数字：把日期、人名、金额、单位与实际来源逐一对照。
  • 容易带过的小词：留意否定词、重复词和缺失的词，读页面上真正出现的文字。
  • 段落连接：需要判断转折是否自然时，退出逐行聚焦，把相邻两段连起来看。
  • 链接和标题：先看上下文是否清楚，再单独打开链接检查目标地址。

LineCheck 不会替你核实事实、测试链接或自动找出错别字。这些检查仍然由你完成。逐行阅读提供一个节奏，颜色则让中途被打断之后的进度不那么模糊。

修改之后，重新检查改过的文字

回到你平时使用的发布工具修改，再刷新预览，检查刚才改动的部分。旧的绿色标记不能证明新句子已经校对；文字变化也可能导致之前的标记无法恢复。

如果换一个重点开始第二轮检查，可以先清除旧标记，让这一轮的颜色继续只代表一件事。发布前，再回到所有未解决的红色段落，决定哪些要改、哪些要核实。最后按 Esc 看一遍完整页面。这时再问自己“检查到哪里了”，眼前已经有具体的线索：哪些看过，哪些改过，哪些问题还没有核实。
